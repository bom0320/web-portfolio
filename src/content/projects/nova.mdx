  title="막막한 전공 선택부터 실제 학습까지, 개발자의 성장 과정을 하나로 연결했습니다."
>

NOVA는 마이스터고 학생들이 **자신에게 맞는 개발 분야를 탐색하고, 선택한 방향을 실제 학습까지 이어갈 수 있도록 만든 개발자 성장 앱**입니다.

학교생활을 하며 주변 학생들이 전공을 선택하는 과정에서 **어떤 분야가 자신에게 맞는지, 무엇부터 공부해야 하는지 알기 어렵다**는 문제를 자주 접했습니다. 필요한 정보와 학습 도구는 이미 많았지만, 자신의 방향을 찾는 과정과 이후의 학습은 서로 분리되어 있었습니다.

NOVA에서는 전공을 단순한 정보로 보여주는 대신, **Frontend · Backend · iOS · Android · NOVA의 특징을 담은 캐릭터 5종을 직접 제작했습니다.** 사용자는 질문을 통해 자신과 가까운 분야를 추천받고, 캐릭터를 직접 비교해 자신의 방향을 선택합니다.

이후 선택한 캐릭터와 함께 미션을 수행하고 성장 상태를 확인하도록 구성해,

> **전공 탐색 → 캐릭터 선택 → 학습 실행 → 성장 확인**

까지 하나의 경험으로 연결했습니다.

팀 리드로 서비스 기획과 기능 우선순위를 조율했으며, React Native 기반 모바일 클라이언트 개발부터 UI 설계와 캐릭터 제작까지 제품 전반을 함께 구현했습니다.

</ProjectDetailSection>

<ProjectDetailSection
  id="problem"
  label="Problem"
  title="정보가 부족한 것보다, 나에게 맞는 방향을 선택하고 이어가는 일이 더 어려웠습니다."
>

마이스터고 학생들에게 전공 선택은 이후의 학습과 취업 방향까지 이어지는 중요한 결정입니다.

하지만 실제 학생들의 이야기를 들어보니 고민은 단순히 **전공에 대한 정보가 부족한 것**에서 끝나지 않았습니다.

여러 개발 분야를 알아보더라도 **어떤 분야가 자신에게 맞는지 판단하기 어렵고**, 관심 있는 분야를 찾은 뒤에도 어떤 공부부터 시작해야 하는지 다시 스스로 결정해야 했습니다.

사용자 조사에서는 다음과 같은 고민이 반복적으로 나타났습니다.

- 선택한 전공이 나에게 맞는지 확신하기 어렵다.
- 전공에 대한 정확한 정보를 어디에서 찾아야 할지 모르겠다.
- 시간이 부족해 무엇부터 공부해야 할지 우선순위를 정하기 어렵다.

기존 서비스도 함께 살펴봤습니다. 강의 플랫폼에서는 학습 콘텐츠를 찾을 수 있었고, Todo·일정 관리 서비스에서는 계획을 관리할 수 있었습니다. 개발 관련 정보를 제공하는 서비스도 이미 존재했습니다.

하지만 각각은 **정보 탐색, 학습, 일정 관리라는 개별 문제를 해결하는 데 집중**하고 있었고, 아직 자신의 방향을 정하지 못한 학생은 **분야를 탐색하고 선택한 뒤 실제 학습까지 이어지는 과정 전체를 스스로 연결해야 했습니다.**

그래서 문제를 단순한 **정보 부족**이 아니라,

> **자신에게 맞는 방향을 발견하고 선택한 뒤, 그 선택을 실제 행동과 성장으로 이어가기 어려운 문제**

로 다시 정의했습니다.

NOVA에서는 이 과정을 하나의 제품 안에서 연결하고자 했습니다.

**탐색 → 선택 → 실행 → 성장 확인**

사용자가 전공 정보를 읽는 데서 멈추지 않고, **어떤 개발자가 되고 싶은지 선택하고 그 방향으로 실제 행동할 수 있는 경험**을 만드는 것을 목표로 했습니다.

</ProjectDetailSection>

#### 사용자가 스스로 방향을 발견할 수 있는 질문에서 시작했습니다.

아직 자신의 관심 분야가 명확하지 않은 학생에게 처음부터 특정 전공을 선택하게 하면 또 다른 부담이 될 수 있다고 생각했습니다. 그래서 NOVA에서는 **웹·앱 개발에 대한 관심, 선호하는 결과물, 개발에서 중요하게 생각하는 요소** 등을 묻는 간단한 질문을 통해 사용자의 성향을 먼저 확인했습니다.

응답을 바탕으로 **Frontend · Backend · iOS · Android · NOVA 중 하나의 분야를 추천**하고, 사용자가 처음부터 모든 전공 정보를 비교해야 하는 부담을 줄이고자 했습니다.

추천은 사용자가 자신의 방향을 생각해보기 위한 **첫 번째 기준**으로만 사용하고, 이후 여러 전공의 캐릭터를 직접 비교한 뒤 최종 선택할 수 있도록 구성했습니다.

![질문을 통해 개발 분야를 탐색하고 추천받는 NOVA 온보딩 화면](/images/projects/nova/detail-12.png)

이를 통해 전공 탐색을 단순히 정보를 읽는 과정이 아니라, 다음 흐름으로 만들었습니다.

> **질문에 답하기 → 나와 가까운 분야 발견하기 → 직접 선택하기**

<h3 id="experience-character">
  02. 전공을 캐릭터라는 시각 언어로 만들었습니다.
</h3>

#### 설명으로만 존재하던 개발 분야를, 선택할 수 있는 정체성으로 표현했습니다.

Frontend, Backend, iOS, Android처럼 개발 분야는 처음 접하는 학생에게 이름과 설명만으로는 각 분야의 차이를 직관적으로 느끼기 어렵다고 생각했습니다.

그래서 전공을 단순한 텍스트나 아이콘으로 구분하는 대신, **각 분야를 하나의 캐릭터로 시각화했습니다.**

**Frontend · Backend · iOS · Android · NOVA 총 5종의 캐릭터를 직접 제작**하고, 일관된 스타일을 유지하면서도 각 전공의 특징이 서로 다른 인상으로 구분되도록 구성했습니다.

캐릭터는 단순히 화면을 꾸미는 장식 요소로 사용하지 않았습니다.

사용자가 설문을 통해 자신과 가까운 분야를 발견한 뒤 해당 전공을 캐릭터로 다시 마주하도록 하면서, 추상적이었던 **“어떤 개발자가 되고 싶은가”라는 선택을 구체적인 대상으로 바꾸고자 했습니다.**

이를 통해 전공을 단순히 이해하는 데서 끝나지 않고, **자신의 방향을 하나의 정체성으로 받아들이고 선택할 수 있는 경험**으로 연결했습니다.

<h3 id="experience-growth">
  03. 선택한 캐릭터를 이후의 성장 경험까지 이어갔습니다.
</h3>

#### 온보딩에서 끝나는 선택이 아니라, 서비스 안에서 계속 마주하도록 했습니다.

전공 캐릭터를 선택하는 경험이 온보딩에서 한 번 사용되고 끝난다면, 단순한 프로필 꾸미기와 크게 다르지 않다고 생각했습니다.

그래서 사용자가 선택한 전공에 맞는 캐릭터를 **메인 홈 화면까지 이어지도록 구성**했습니다. Frontend · Backend · iOS · Android · NOVA 각각에 대응하는 홈 캐릭터 이미지를 연결하고, 최종 선택한 캐릭터 정보를 다음 화면으로 전달했습니다.

메인 화면에서는 자신의 캐릭터와 함께 학습 미션을 확인하고 완료할 수 있도록 했으며, 별도의 성장 화면에서는 현재 개발자 단계와 수행 기록을 확인하도록 구성했습니다.

이를 통해 캐릭터를 한 번 선택하고 사라지는 요소가 아니라, **처음 선택한 전공과 이후의 학습 경험을 연결하는 시각적인 기준**으로 활용했습니다.

> **전공 선택 → 나의 캐릭터 → 미션 수행 → 성장 확인**

</ProjectDetailSection>

<span id="engineering-onboarding" className="project-detail-section__anchor" />

설문에서 선택한 답변은 상태로 관리하고, 모든 질문에 응답했을 때 답변 조합을 기준으로 `FrontEnd`, `BackEnd`, `iOS`, `Android`, `Nova` 중 하나의 `recommendedMajor`를 결정했습니다.

추천 결과는 별도의 결과 화면에서 끝내지 않고 **다음 화면의 상태로 전달했습니다.** `recommendedMajor`에 해당하는 캐릭터가 캐러셀에서 먼저 노출되도록 순서를 변경하고, 사용자가 최종적으로 선택한 캐릭터는 다시 메인 화면까지 전달했습니다.

> **설문 응답 → 전공 추천 → 캐릭터 제안 → 사용자 선택 → 메인 경험**

이를 통해 한 화면에서 발생한 사용자의 입력이 사라지지 않고, **이후 화면의 상태와 콘텐츠까지 변화시키는 하나의 온보딩 흐름으로 연결했습니다.**

<h3 id="engineering-ai-state">
  02. AI의 응답 시간을 모바일 인터랙션의 상태로 다뤘습니다.
</h3>

NOVA에서는 무엇을 공부해야 할지 막막한 사용자가 질문할 수 있도록 OpenAI Chat Completions API를 모바일 클라이언트에 연결했습니다.

AI 응답은 즉시 반환되지 않기 때문에 결과만 화면에 추가하는 대신, **응답을 기다리는 과정까지 대화의 상태로 처리했습니다.**

사용자가 메시지를 보내면 자신의 메시지를 먼저 대화 목록에 반영하고, 응답을 기다리는 동안 로딩 상태를 노출했습니다. 응답이 도착하면 AI 메시지를 추가하고, 요청에 실패한 경우에는 오류 메시지를 대화 흐름 안에서 보여주도록 구성했습니다.

또한 모바일에서 키보드가 올라왔을 때도 입력 영역과 대화 목록이 유지되도록 처리했습니다.

> **입력 → 사용자 메시지 반영 → 응답 대기 → AI 응답 / 실패**

외부 API를 연결하는 데서 끝내지 않고, **비동기 응답의 대기와 실패 상태까지 사용자가 인지할 수 있는 모바일 인터랙션으로 구현했습니다.**

<h3 id="engineering-growth">
  03. 학습 행동이 시각적인 성장으로 돌아오도록 프로토타이핑했습니다.
</h3>

홈에서는 사용자가 미션을 완료하면 해당 미션을 완료 상태로 변경하고, 아직 남아 있는 미션과 구분해 완료된 항목이 목록의 아래로 이동하도록 구현했습니다.

한 번의 완료 상태에서 끝내지 않고, MY 화면에서는 프로필·레벨·개발자 단계·완료 기록을 함께 보여주며 **현재까지의 성장 상태를 다시 확인할 수 있도록 구성했습니다.**

또한 미션 수행량을 월 단위 보드의 명도 차이로 표현해, **반복되는 학습 행동이 얼마나 쌓였는지를 시각적으로 확인하는 방식**을 프로토타이핑했습니다. 하루 동안 완료한 미션 수에 따라 각 셀의 표현 강도가 달라지도록 구성했습니다.

> **미션 수행 → 완료 상태 변화 → 누적 기록 → 성장 단계 확인**

이를 통해 미션을 한 번 완료하는 순간의 피드백에서 끝나지 않고, **시간이 지나며 쌓이는 학습 행동을 성장의 형태로 다시 보여주고자 했습니다.**

</ProjectDetailSection>

<ProjectDetailSection
  id="retrospective"
  label="Retrospective"
  title="기능을 만드는 것보다, 사용자의 다음 행동을 설계하는 법을 배웠습니다."
>

NOVA를 시작할 때는 전공 정보를 더 쉽게 제공하면 학생들의 고민을 해결할 수 있다고 생각했습니다.

하지만 실제 사용자 조사를 진행하면서 문제는 정보의 양보다, **자신에게 맞는 방향을 판단하고 그다음 행동까지 스스로 연결해야 한다는 점**에 있다는 것을 알게 됐습니다.

그래서 서비스의 중심을 단순한 정보 제공이 아니라,

> **탐색 → 선택 → 실행 → 성장 확인**

으로 다시 정리했습니다.

전공을 캐릭터라는 시각적인 정체성으로 표현하고, 질문을 통한 탐색과 캐릭터 선택, 미션 수행과 성장 확인을 하나의 흐름으로 연결하면서 **각 기능의 완성도보다 사용자가 다음 행동으로 자연스럽게 넘어갈 수 있는지를 기준으로 제품을 설계했습니다.**

팀 리드로 기획·디자인·개발을 함께 다루면서도 같은 기준을 배웠습니다. 좋은 아이디어를 많이 넣는 것보다, **제품이 해결하려는 문제를 중심으로 서로 다른 기능과 팀의 결정을 하나의 방향으로 모으는 것이 중요했습니다.**

NOVA는 처음으로 화면 구현을 넘어 **사용자 문제를 직접 정의하고, 시각적인 컨셉을 만들고, 이를 실제 모바일 인터랙션까지 연결해본 프로젝트**였습니다.

이 경험 이후 기능 자체보다 **“왜 이 기능이 필요한지, 사용자의 경험 안에서 어떤 역할을 하는지”** 를 먼저 생각하게 됐습니다.

프로젝트는 광주SW마이스터고 아이디어 페스티벌에서 **최우수상(교내 1위)** 을 수상했습니다.

</ProjectDetailSection>
